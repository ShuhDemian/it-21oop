  ## Хід роботи

  1. Дати загальний опис принципів рефакторингу. 

Рефакторинг — це зміна внутрішньої будови коду без зміни того, що програма робить зовні. Тобто код стає чистішим, зрозумілішим і простішим для підтримки, а результат його роботи залишається тим самим.

Головні принципи такі. Рефакторинг не додає нових функцій і не виправляє помилки, він лише покращує структуру. Його роблять маленькими кроками, і після кожного кроку перевіряють, що все працює. Для перевірки зазвичай використовують тести: якщо вони проходили до рефакторингу, мають проходити й після нього. Рефакторинг виконують регулярно, а не «колись потім», бо чим довше накопичується безлад у коді, тим складніше його розібрати. Також його не змішують з додаванням нових можливостей: спочатку покращуємо структуру, потім додаємо нове (або навпаки), але не одночасно.

Навіщо це потрібно: код легше читати, легше знаходити помилки, простіше додавати нові функції, зменшується ризик зламати щось при змінах.


  2. Ознайомитися із основними техніками рефакторингу. Детально описати одну із технік. 

Найпоширеніші техніки: Extract Method (виділення методу: частина коду виноситься в окрему функцію), Rename (перейменування: змінна, функція чи клас отримує зрозумілішу назву), Inline Method (вбудовування методу: надто проста функція замінюється її тілом), Extract Class (виділення класу: частина обов'язків великого класу виноситься в новий клас), Replace Magic Number with Constant (заміна «магічного числа» на іменовану константу), Move Method (перенесення методу в той клас, якому він більше підходить).

Детально: Extract Method (Виділення методу)

Суть. Якщо у функції є фрагмент коду, який виконує окрему задачу, його виносять в нову функцію з зрозумілою назвою. На місці фрагмента залишається виклик цієї функції.

Коли застосовувати. Коли функція задовга, коли частину коду потрібно пояснювати коментарем, або коли один і той самий фрагмент повторюється в кількох місцях.

Приклад до рефакторингу:

`def print_receipt(price, quantity):`

`    total = price * quantity`

`    if total > 1000:`

`        total = total * 0.9`

`    print("Чек")`

`    print("Сума:", total)`

`print_receipt(600, 2)`


Приклад після рефакторингу:

`def calculate_total(price, quantity):`

`    total = price * quantity`

`    if total > 1000:`

`        total = total * 0.9`

`    return total`

`def print_receipt(price, quantity):`

`    total = calculate_total(price, quantity)`

`    print("Чек")`

`    print("Сума:", total)`

`print_receipt(600, 2)`


  3. Познайомитися із поняттям “запахів коду”. Дати детальний опис одного із “запахів”. 

«Запах коду» — це ознака в коді, яка натякає на можливу проблему в проєктуванні. Це не помилка: програма може працювати правильно, але такий код складно читати і змінювати. Запах підказує, що варто зробити рефакторинг. Серед найвідоміших: Long Method (задовгий метод), Large Class (завеликий клас), Duplicate Code (дублювання коду), Long Parameter List (забагато параметрів), Magic Numbers (незрозумілі числа в коді).

Детально: Duplicate Code (Дублювання коду)

Суть. Той самий або дуже схожий фрагмент коду повторюється в кількох місцях програми.

Чому це погано. Якщо потрібно щось змінити, доведеться виправляти кожне місце окремо. Легко забути про одне з них, і тоді з'являються помилки. Крім того, програма стає довшою й заплутанішою.

Приклад із "запахом":

`def area_square(a):`

`    print("Обчислюю площу")`

`    return a * a`

`def area_rectangle(a, b):`

`    print("Обчислюю площу")`

`    return a * b`

Як виправити? Об'єднати їх в одну функцію:

`def area(a, b):`

`    print("Обчислюю площу")`

`    return a * b`

`print(area(3, 3))  # квадрат`

`print(area(2, 5))  # прямокутник`
