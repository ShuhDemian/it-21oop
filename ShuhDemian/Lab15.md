## Завдання 1. Загальний опис принципів рефакторингу

**Рефакторинг програмного забезпечення** — це процес зміни внутрішньої структури програмного коду без зміни його зовнішньої поведінки. Його основна мета — зробити код зрозумілішим, простішим для підтримки та зручнішим для подальшого розвитку.

Основні принципи рефакторингу:

1. **Збереження поведінки програми.** Після рефакторингу програма повинна виконувати ті самі функції, що й до внесення змін.
2. **Поступовість змін.** Рефакторинг краще виконувати невеликими кроками, перевіряючи результат після кожної зміни.
3. **Використання автоматизованих тестів.** Тести допомагають переконатися, що зміни не спричинили помилок.
4. **Покращення читабельності коду.** Назви змінних, методів і класів повинні зрозуміло відображати їхнє призначення.
5. **Усунення дублювання.** Повторюваний код варто винести в окремі функції або методи.
6. **Дотримання принципу єдиної відповідальності.** Клас або функція повинні мати чітке призначення.
7. **Регулярність.** Рефакторинг доцільно проводити під час розробки, коли виявляються проблеми зі структурою коду.

Рефакторинг не призначений для додавання нових функцій. Його завдання — покращити внутрішню організацію програми, зберігаючи її поведінку.

## Завдання 2. Основні техніки рефакторингу та детальний опис однієї з них

### 2.1. Основні техніки рефакторингу

До найбільш поширених технік рефакторингу належать:

- **Rename Variable (Перейменування змінної)** — зміна назви змінної на зрозумілішу.
- **Extract Method (Виділення методу)** — винесення частини коду в окремий метод.
- **Inline Method (Вбудовування методу)** — заміна виклику методу його тілом, якщо окремий метод більше не потрібний.
- **Extract Class (Виділення класу)** — перенесення частини обов'язків класу до нового класу.
- **Move Method (Переміщення методу)** — перенесення методу до класу, якому він більше відповідає за призначенням.
- **Replace Magic Number with Constant (Заміна магічного числа константою)** — заміна незрозумілого числового значення іменованою константою.
- **Remove Duplicate Code (Усунення дублювання коду)** — об'єднання повторюваних фрагментів у спільну функцію або метод.
- **Encapsulate Field (Інкапсуляція поля)** — обмеження прямого доступу до поля через методи або властивості.
- **Simplify Conditional Expression (Спрощення умовного виразу)** — спрощення складних умов для кращого розуміння коду.

### 2.2. Детальний опис техніки Extract Method (Виділення методу)

**Extract Method** — це техніка рефакторингу, за якої окремий фрагмент коду переноситься в новий метод із назвою, що описує його призначення.

Ця техніка використовується, коли функція містить багато рядків коду, виконує декілька дій або має фрагмент, який можна логічно відокремити.

Основні переваги:

- код стає зрозумілішим;
- зменшується довжина основного методу;
- повторювані операції можна використовувати повторно;
- спрощується тестування та пошук помилок;
- кожен метод виконує конкретне завдання.

#### Приклад до рефакторингу

```python
def show_order():
    name = "Ноутбук"
    price = 25000
    quantity = 2

    total = price * quantity

    print("Товар:", name)
    print("Кількість:", quantity)
    print("Загальна вартість:", total)


show_order()
```

#### Приклад після рефакторингу

```python
def calculate_total(price, quantity):
    return price * quantity


def print_order(name, quantity, total):
    print("Товар:", name)
    print("Кількість:", quantity)
    print("Загальна вартість:", total)


def show_order():
    name = "Ноутбук"
    price = 25000
    quantity = 2

    total = calculate_total(price, quantity)
    print_order(name, quantity, total)


show_order()
```

#### Пояснення

У першому прикладі одна функція виконує всі дії: зберігає інформацію про товар, обчислює вартість і виводить результат.

Після рефакторингу код розділено на три функції:

- `calculate_total()` обчислює загальну вартість;
- `print_order()` виводить інформацію про замовлення;
- `show_order()` організовує виконання програми.

Результат роботи програми не змінюється, але код стає структурованішим і простішим для розуміння.

## Завдання 3. Поняття «запахів коду» та детальний опис одного із запахів

### 3.1. Поняття «запахів коду»

**Запахи коду (Code Smells)** — це ознаки в програмному коді, які можуть свідчити про проблеми з його структурою, читабельністю або можливістю підтримки. Вони не обов'язково означають наявність помилки, але вказують на ділянки, які варто перевірити та, за потреби, покращити за допомогою рефакторингу.

До поширених запахів коду належать:

- **Duplicated Code (Дублювання коду)** — однакові або дуже схожі фрагменти повторюються в різних місцях програми.
- **Long Method (Довгий метод)** — метод виконує забагато дій і його складно зрозуміти.
- **Large Class (Великий клас)** — клас має надто багато обов'язків.
- **Long Parameter List (Довгий список параметрів)** — метод приймає забагато параметрів.
- **Feature Envy (Заздрість до функціональності)** — метод частіше використовує дані іншого класу, ніж власного.
- **Magic Numbers (Магічні числа)** — у коді використовуються числові значення без пояснення їхнього призначення.
- **Shotgun Surgery (Розсіяні зміни)** — одна зміна функціональності вимагає редагування багатьох різних класів або методів.

Виявлення запахів коду допомагає визначити, де структура програми потребує вдосконалення.

### 3.2. Детальний опис запаху коду Duplicated Code (Дублювання коду)

**Duplicated Code** — це запах коду, який виникає, коли однакові або майже однакові фрагменти програмного коду повторюються в декількох місцях.

Дублювання ускладнює підтримку програми. Якщо потрібно змінити повторювану логіку, доводиться знаходити та редагувати кожен її екземпляр. Якщо один фрагмент не буде оновлено, програма може працювати непослідовно.

#### Приклад коду з дублюванням

```python
def calculate_price_one():
    price = 100
    quantity = 3
    total = price * quantity
    print("Вартість:", total)


def calculate_price_two():
    price = 200
    quantity = 2
    total = price * quantity
    print("Вартість:", total)


calculate_price_one()
calculate_price_two()
```

У цьому прикладі обчислення загальної вартості повторюється у двох функціях. Якщо потрібно змінити спосіб обчислення або формат виведення, доведеться редагувати обидві функції.

#### Виправлення за допомогою рефакторингу

```python
def calculate_price(price, quantity):
    total = price * quantity
    print("Вартість:", total)


calculate_price(100, 3)
calculate_price(200, 2)
```

Після рефакторингу спільну логіку винесено у функцію `calculate_price()`. Тепер її можна викликати з різними значеннями ціни та кількості товару.

#### Переваги усунення дублювання

- зменшується кількість повторюваного коду;
- спрощується внесення змін;
- зменшується ризик помилок;
- код стає компактнішим і зрозумілішим;
- покращується можливість повторного використання логіки.
