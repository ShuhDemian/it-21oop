## Завдання 1. Теоретичний опис поведінкової групи шаблонів

**Поведінкові шаблони проєктування** — це шаблони, які визначають способи взаємодії між об'єктами та розподілу обов'язків між ними. Вони допомагають організувати обмін інформацією між компонентами програми, спростити керування поведінкою об'єктів і зробити програмний код гнучкішим.

До основних поведінкових шаблонів належать:

- **Chain of Responsibility (Ланцюжок обов'язків)** — передає запит послідовно між об'єктами, доки його не буде оброблено.
- **Command (Команда)** — перетворює запит на окремий об'єкт.
- **Interpreter (Інтерпретатор)** — визначає правила інтерпретації виразів певної мови.
- **Iterator (Ітератор)** — забезпечує послідовний доступ до елементів колекції.
- **Mediator (Посередник)** — організовує взаємодію об'єктів через окремий об'єкт-посередник.
- **Memento (Знімок)** — дає змогу зберігати та відновлювати попередній стан об'єкта.
- **Observer (Спостерігач)** — повідомляє залежні об'єкти про зміни стану іншого об'єкта.
- **State (Стан)** — дозволяє об'єкту змінювати поведінку залежно від поточного стану.
- **Strategy (Стратегія)** — дає змогу вибирати між різними алгоритмами.
- **Template Method (Шаблонний метод)** — визначає загальну структуру алгоритму, залишаючи окремі кроки для реалізації в підкласах.
- **Visitor (Відвідувач)** — дозволяє додавати нові операції для об'єктів без зміни їхніх класів.

Використання поведінкових шаблонів полегшує організацію взаємодії між об'єктами, зменшує залежність між компонентами та спрощує підтримку програмного забезпечення.

## Завдання 2. Шаблон Observer (Спостерігач)

### 2.1. Теоретичний опис шаблону

**Observer (Спостерігач)** — це поведінковий шаблон проєктування, який встановлює залежність між об'єктом, за яким спостерігають, і набором об'єктів-спостерігачів. Коли стан основного об'єкта змінюється, усі зареєстровані спостерігачі автоматично отримують повідомлення про цю зміну.

Основними елементами шаблону є:

- **Subject (Суб'єкт)** — об'єкт, який зберігає список спостерігачів і повідомляє їх про зміни.
- **Observer (Спостерігач)** — інтерфейс або абстрактний клас для отримання повідомлень.
- **ConcreteObserver (Конкретний спостерігач)** — реалізація спостерігача, яка виконує потрібні дії після отримання повідомлення.

Цей шаблон можна використовувати для систем сповіщень, оновлення інтерфейсу користувача, моніторингу стану пристроїв та інших завдань, де кілька об'єктів повинні реагувати на одну подію.

### 2.2. Приклад коду мовою Python

У прикладі створено систему сповіщень про зміну температури. Коли температура змінюється, усі зареєстровані спостерігачі отримують повідомлення.

```python
from abc import ABC, abstractmethod


class Observer(ABC):
    @abstractmethod
    def update(self, temperature):
        pass


class Phone(Observer):
    def update(self, temperature):
        print(f"Телефон: температура змінилася на {temperature}°C")


class Display(Observer):
    def update(self, temperature):
        print(f"Дисплей: поточна температура {temperature}°C")


class WeatherStation:
    def __init__(self):
        self.observers = []
        self.temperature = 0

    def add_observer(self, observer):
        self.observers.append(observer)

    def set_temperature(self, temperature):
        self.temperature = temperature
        self.notify_observers()

    def notify_observers(self):
        for observer in self.observers:
            observer.update(self.temperature)


station = WeatherStation()

phone = Phone()
display = Display()

station.add_observer(phone)
station.add_observer(display)

station.set_temperature(25)
```

### Результат виконання програми

```text
Телефон: температура змінилася на 25°C
Дисплей: поточна температура 25°C
```

### 2.3. UML-діаграма шаблону

```text
              <<abstract>>
          ┌───────────────────┐
          │     Observer      │
          ├───────────────────┤
          │ + update(temp)    │
          └─────────△─────────┘
                    │
           ┌────────┴────────┐
           │                 │
    ┌──────────────┐  ┌──────────────┐
    │    Phone     │  │   Display    │
    ├──────────────┤  ├──────────────┤
    │+update(temp) │  │+update(temp) │
    └──────────────┘  └──────────────┘
           ▲                 ▲
           │                 │
           └────────┬────────┘
                    │ повідомлення
                    │
          ┌──────────────────────┐
          │    WeatherStation    │
          ├──────────────────────┤
          │ - observers           │
          │ - temperature         │
          ├──────────────────────┤
          │ + add_observer()      │
          │ + set_temperature()   │
          │ + notify_observers()  │
          └──────────────────────┘
```

### Пояснення UML-діаграми

- `Observer` — абстрактний клас, який визначає метод `update()`.
- `Phone` — конкретний спостерігач, який виводить повідомлення про зміну температури.
- `Display` — конкретний спостерігач, який показує поточну температуру.
- `WeatherStation` — об'єкт, що зберігає температуру, реєструє спостерігачів і повідомляє їх про зміни.

Коли викликається метод `set_temperature()`, об'єкт `WeatherStation` оновлює температуру та викликає метод `notify_observers()`. Після цього всі зареєстровані спостерігачі отримують нове значення температури.
