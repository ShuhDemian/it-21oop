# Завдання 1. Теоретичний опис структурної групи шаблонів

**Структурні шаблони проєктування** — це шаблони, які описують способи організації класів і об'єктів у програмі для створення гнучких та зручних у використанні структур.

Їх основна мета — спростити взаємодію між компонентами програми, забезпечити повторне використання коду та зменшити залежність між окремими частинами системи.

До структурних шаблонів належать:

- **Adapter (Адаптер)** — забезпечує сумісність класів із різними інтерфейсами.
- **Bridge (Міст)** — відокремлює абстракцію від її реалізації.
- **Composite (Компонувальник)** — дозволяє працювати з окремими об'єктами та їх групами однаково.
- **Decorator (Декоратор)** — додає об'єктам нову функціональність без зміни їхніх класів.
- **Facade (Фасад)** — надає спрощений інтерфейс для роботи зі складною підсистемою.
- **Flyweight (Пристосуванець)** — зменшує використання пам'яті завдяки повторному використанню спільних даних.
- **Proxy (Замісник)** — контролює доступ до іншого об'єкта.

Використання структурних шаблонів допомагає створювати програми, які легше розширювати, підтримувати та змінювати.

# Завдання 2. Шаблон Adapter (Адаптер)

# 2.1. Теоретичний опис шаблону

**Adapter (Адаптер)** — це структурний шаблон проєктування, який дозволяє об'єктам із несумісними інтерфейсами працювати разом. Він перетворює інтерфейс одного класу на інтерфейс, який очікує інший клас.

Адаптер використовується тоді, коли потрібно застосувати готовий клас у програмі, але його інтерфейс не відповідає вимогам системи.

Основні учасники шаблону:

- **Target** — інтерфейс, який очікує клієнтський код.
- **Adaptee** — клас із наявним, але несумісним інтерфейсом.
- **Adapter** — клас, який перетворює інтерфейс Adaptee на потрібний інтерфейс Target.
- **Client** — код, який працює з об'єктом через інтерфейс Target.

Перевага шаблону Adapter полягає в тому, що він дозволяє використовувати наявні класи без необхідності змінювати їхній вихідний код.

## 2.2. Приклад коду на Python

У прикладі є клас, який відтворює звук через метод `specific_sound()`, але клієнтський код очікує метод `play()`. Адаптер забезпечує сумісність цих інтерфейсів.

```python
from abc import ABC, abstractmethod


class Target(ABC):
    @abstractmethod
    def play(self):
        pass


class OldPlayer:
    def specific_sound(self):
        return "Відтворення звуку"


class PlayerAdapter(Target):
    def __init__(self, player):
        self.player = player

    def play(self):
        return self.player.specific_sound()


player = PlayerAdapter(OldPlayer())
print(player.play())
```

Результат виконання:

```text
Відтворення звуку
```

**Пояснення роботи програми:**

1. `Target` визначає метод `play()`, який очікує клієнтський код.
2. `OldPlayer` має власний метод `specific_sound()`, тому його інтерфейс несумісний із Target.
3. `PlayerAdapter` реалізує метод `play()` і викликає через нього метод `specific_sound()` об'єкта OldPlayer.
4. Клієнтський код викликає `play()` і отримує потрібний результат без зміни класу OldPlayer.

# 2.3. UML-діаграма

```text
              <<abstract>>
          ┌──────────────────┐
          │      Target      │
          ├──────────────────┤
          │ + play()         │
          └────────▲─────────┘
                   │
          ┌────────┴─────────┐
          │  PlayerAdapter   │
          ├──────────────────┤
          │ - player         │
          │ + play()         │
          └────────┬─────────┘
                   │
                   │ використовує
                   ▼
          ┌──────────────────┐
          │    OldPlayer     │
          ├──────────────────┤
          │ + specific_sound()│
          └──────────────────┘
```

На UML-діаграмі `Target` визначає потрібний інтерфейс. `PlayerAdapter` реалізує цей інтерфейс і використовує об'єкт `OldPlayer`, який має інший метод. Таким чином, адаптер забезпечує взаємодію між класами з несумісними інтерфейсами.
