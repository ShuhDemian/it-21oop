# 1.Дати загальний опис принципів проєктування.

Принципи проєктування програмного забезпечення — це набір рекомендацій, які допомагають створювати зрозумілий, гнучкий, надійний і зручний для підтримки код. Їх застосування дозволяє зменшити складність програми, уникнути дублювання коду та полегшити внесення змін у майбутньому.

Одними з найвідоміших принципів є:

SOLID — п'ять принципів об'єктно-орієнтованого програмування, які допомагають створювати гнучку архітектуру.
DRY (Don't Repeat Yourself) — не слід дублювати однаковий код у різних частинах програми.
KISS (Keep It Simple, Stupid) — програмне рішення повинно бути максимально простим.
YAGNI (You Aren't Gonna Need It) — не потрібно реалізовувати функції, які можуть знадобитися лише в майбутньому.
Separation of Concerns — різні частини програми повинні відповідати за окремі завдання.

Принципи SOLID включають:

S — Single Responsibility Principle — принцип єдиної відповідальності.
O — Open/Closed Principle — принцип відкритості та закритості.
L — Liskov Substitution Principle — принцип підстановки Барбари Лісков.
I — Interface Segregation Principle — принцип розділення інтерфейсів.
D — Dependency Inversion Principle — принцип інверсії залежностей.

Дотримання цих принципів робить програмний код більш структурованим, зрозумілим і простішим для подальшого розвитку.
# 2. Дати детальний опис одного із принципів SOLID з наведення прикладу коду.

Single Responsibility Principle (SRP) або принцип єдиної відповідальності означає, що кожен клас повинен мати лише одну основну відповідальність або одну причину для зміни.

Наприклад, клас, який зберігає інформацію про користувача, не повинен одночасно відповідати за друк цієї інформації у файл. Краще розділити ці завдання між різними класами.

Приклад неправильного проєктування
```
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def get_info(self):
        return f"Ім'я: {self.name}, Вік: {self.age}"

    def save_to_file(self):
        with open("student.txt", "w", encoding="utf-8") as file:
            file.write(self.get_info())
```

У цьому прикладі клас Student має дві відповідальності:

зберігає інформацію про студента;
працює з файлами.

Це порушує принцип SRP.

Правильне застосування принципу SRP
```
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def get_info(self):
        return f"Ім'я: {self.name}, Вік: {self.age}"


class StudentFileManager:
    def save_to_file(self, student):
        with open("student.txt", "w", encoding="utf-8") as file:
            file.write(student.get_info())


student = Student("Іван", 20)

file_manager = StudentFileManager()
file_manager.save_to_file(student)
```
