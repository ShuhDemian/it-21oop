### 1. Види тестів та піраміда тестування

**Тестування** — процес перевірки відповідності програми вимогам з метою виявлення дефектів. Автоматизовані тести дозволяють швидко й повторювано перевіряти поведінку програми, у тому числі після змін та рефакторингу.

| Вид тестування | Що перевіряє | Переваги | Недоліки |
| --- | --- | --- | --- |
| Unit (модульне) | Окремі функції, методи, класи в ізоляції | Швидкі, дешеві, точно вказують на місце помилки | Не виявляють проблем взаємодії модулів |
| Integration (інтеграційне) | Взаємодію кількох модулів (код + БД, API) | Знаходять помилки на стику компонентів | Повільніші, складніші в налаштуванні |
| E2E (наскрізне) | Повний сценарій користувача через увесь застосунок | Імітують реальне використання | Повільні, крихкі, дорогі в підтримці |

**Піраміда тестування:** найбільше має бути швидких unit-тестів, менше — інтеграційних і найменше — E2E.

```
          /\
         /E2E\          мало, повільні, дорогі
        /------\
       /Integra-\       середня кількість
      /  tion    \
     /------------\
    /     Unit     \    багато, швидкі, дешеві
   /________________\
```

У процесі розробки також застосовують функціональне, регресійне, навантажувальне тестування, тестування безпеки та приймальне тестування. Методологія **TDD** (Test-Driven Development) передбачає цикл «Red → Green → Refactor»: спочатку пишемо тест, що не проходить, потім мінімальний код, щоб він пройшов, потім покращуємо код.

### 2. Unit-тест на Python з використанням модуля unittest

Модуль `unittest` входить до стандартної бібліотеки Python. Тестовий клас успадковується від `unittest.TestCase`; перевірки виконуються методами `assertEqual`, `assertAlmostEqual`, `assertRaises` тощо. Метод `setUp()` виконується перед кожним тестом і готує оточення.

#### 2.1. Код, що тестується (файл cart.py)

```
class ShoppingCart:
    def __init__(self):
        self.items = []

    def add(self, name, price, qty=1):
        if price < 0 or qty <= 0:
            raise ValueError('Некоректна ціна або кількість')
        self.items.append((name, price, qty))

    def total(self, discount=0.0):
        return sum(price * qty for _, price, qty in self.items) * (1 - discount)
```

#### 2.2. Тести (файл test\_cart.py)

```
import unittest
from cart import ShoppingCart


class TestShoppingCart(unittest.TestCase):

    def setUp(self):
        self.cart = ShoppingCart()                      # Arrange

    def test_empty_cart_total_is_zero(self):
        self.assertEqual(self.cart.total(), 0)

    def test_total_sums_items(self):
        self.cart.add('Хліб', 20, 2)
        self.cart.add('Молоко', 35)
        self.assertEqual(self.cart.total(), 75)         # Act + Assert

    def test_total_with_discount(self):
        self.cart.add('Корм', 100)
        self.assertAlmostEqual(self.cart.total(0.1), 90)

    def test_negative_price_raises_error(self):
        with self.assertRaises(ValueError):
            self.cart.add('Помилка', -5)


if __name__ == '__main__':
    unittest.main()
```

#### 2.3. Запуск тестів

Тести запускаються командою:

```
python -m unittest test_cart.py -v
```

Очікуваний результат:

```
test_empty_cart_total_is_zero (test_cart.TestShoppingCart) ... ok
test_negative_price_raises_error (test_cart.TestShoppingCart) ... ok
test_total_sums_items (test_cart.TestShoppingCart) ... ok
test_total_with_discount (test_cart.TestShoppingCart) ... ok

----------------------------------------------------------------------
Ran 4 tests in 0.001s

OK
```

#### 2.4. Пояснення

Кожен тест перевіряє одну поведінку й працює незалежно від інших, оскільки `setUp()` створює новий кошик перед кожним тестом. Структура тесту відповідає схемі AAA: Arrange (підготовка), Act (виклик), Assert (перевірка). Тест `test_negative_price_raises_error` перевіряє, що некоректні дані спричиняють очікуване виключення.
