Мета роботи
Познайомитися з найбільш поширеними сучасними принципами проєктування програмного забезпечення.
1. Загальний опис принципів проєктування
Принципи проєктування програмного забезпечення — це набір рекомендацій, які допомагають створювати зрозумілий, гнучкий, надійний і зручний для підтримки код. Їх застосування зменшує складність програми, допомагає уникнути дублювання коду та полегшує внесення змін у майбутньому.
Найвідоміші принципи:
• SOLID — п'ять принципів об'єктно-орієнтованого проєктування, які допомагають створювати гнучку архітектуру.
• DRY (Don't Repeat Yourself) — не слід дублювати однаковий код у різних частинах програми.
• KISS (Keep It Simple, Stupid) — програмне рішення має бути максимально простим.
• YAGNI (You Aren't Gonna Need It) — не слід реалізовувати функції, які можуть знадобитися лише в майбутньому.
• Separation of Concerns — різні частини програми мають відповідати за окремі завдання.
Принципи SOLID:
• S — Single Responsibility Principle (принцип єдиної відповідальності);
• O — Open/Closed Principle (принцип відкритості/закритості);
• L — Liskov Substitution Principle (принцип підстановки Барбари Лісков);
• I — Interface Segregation Principle (принцип розділення інтерфейсів);
• D — Dependency Inversion Principle (принцип інверсії залежностей).
Дотримання цих принципів робить код більш структурованим, зрозумілим і простішим для подальшого розвитку.
2. Детальний опис принципу SRP з прикладом коду
Single Responsibility Principle (SRP), або принцип єдиної відповідальності, означає, що кожен клас повинен мати лише одну основну відповідальність, тобто одну причину для зміни.
Наприклад, клас, який зберігає інформацію про студента, не повинен одночасно відповідати за запис цієї інформації у файл. Ці завдання краще розділити між різними класами.
Неправильне проєктування (порушення SRP):
""
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def get_info(self):
        return f"Ім'я: {self.name}, Вік: {self.age}"

    def save_to_file(self):
        with open("student.txt", "w", encoding="utf-8") as file:
            file.write(self.get_info())
Клас Student має дві відповідальності: зберігає інформацію про студента та працює з файлами. Якщо зміниться формат збереження, доведеться змінювати клас, який описує студента.
Правильне застосування SRP:
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def get_info(self):
        return f"Ім'я: {self.name}, Вік: {self.age}"


class StudentFileManager:
    def save_to_file(self, student):
        with open("student.txt", "w", encoding="utf-8") as file:
            file.write(student.get_info())


student = Student("Іван", 20)
file_manager = StudentFileManager()
file_manager.save_to_file(student)
""
