### Мета роботи

Познайомитися з групою твірних шаблонів проєктування.

### 1. Теоретичний опис групи твірних шаблонів

**Твірні (породжувальні) шаблони** абстрагують процес створення об'єктів. Вони роблять систему незалежною від того, як саме створюються, компонуються та подаються її об'єкти. Пряме створення об'єктів через конструктор жорстко прив'язує код до конкретних класів, ускладнює їх заміну та тестування.

Основні твірні шаблони:

- **Singleton (Одинак)** — гарантує один екземпляр класу та глобальну точку доступу до нього;
- **Factory Method (Фабричний метод)** — визначає інтерфейс створення об'єкта, а підкласи вирішують, який клас інстанціювати;
- **Abstract Factory (Абстрактна фабрика)** — створює сімейства взаємопов'язаних об'єктів;
- **Builder (Будівельник)** — покроково будує складний об'єкт;
- **Prototype (Прототип)** — створює нові об'єкти клонуванням існуючих.

### 2. Шаблон «Фабричний метод» (Factory Method)

#### 2.1. Теоретичний опис

**Фабричний метод** — це твірний шаблон, який визначає в базовому класі метод створення об'єкта-продукту, а підкласи перевизначають його, вирішуючи, об'єкт якого саме класу створювати. Клієнтський код працює лише з абстракцією (інтерфейсом продукту) й не знає конкретних класів.

Учасники шаблону:

- **Product** (`Transport`) — спільний інтерфейс продуктів;
- **ConcreteProduct** (`Truck`, `Ship`) — конкретні продукти;
- **Creator** (`Logistics`) — оголошує фабричний метод `create_transport()` і містить логіку, що його використовує;
- **ConcreteCreator** (`RoadLogistics`, `SeaLogistics`) — перевизначають фабричний метод і повертають конкретний продукт.

Переваги: слабка зв'язаність, відповідність принципам SRP та OCP (нові продукти додаються без зміни наявного коду). Недолік: збільшується кількість класів.

#### 2.2. Приклад реалізації коду (Python)

```
from abc import ABC, abstractmethod


class Transport(ABC):                      # Product
    @abstractmethod
    def deliver(self, cargo):
        pass


class Truck(Transport):                    # ConcreteProduct
    def deliver(self, cargo):
        return f"Вантаж '{cargo}' доставлено вантажівкою по суші"


class Ship(Transport):                     # ConcreteProduct
    def deliver(self, cargo):
        return f"Вантаж '{cargo}' доставлено кораблем морем"


class Logistics(ABC):                      # Creator
    @abstractmethod
    def create_transport(self):            # фабричний метод
        pass

    def plan_delivery(self, cargo):
        transport = self.create_transport()
        return transport.deliver(cargo)


class RoadLogistics(Logistics):            # ConcreteCreator
    def create_transport(self):
        return Truck()


class SeaLogistics(Logistics):             # ConcreteCreator
    def create_transport(self):
        return Ship()


if __name__ == "__main__":
    for logistics in (RoadLogistics(), SeaLogistics()):
        print(logistics.plan_delivery("Ветеринарні препарати"))
```

Результат виконання:

```
Вантаж 'Ветеринарні препарати' доставлено вантажівкою по суші
Вантаж 'Ветеринарні препарати' доставлено кораблем морем
```

#### 2.3. UML-діаграма класів

```
  +-----------------------+   creates   +--------------------+
  |   Logistics (ABC)     |------------>|  Transport (ABC)   |
  +-----------------------+             +--------------------+
  | + create_transport()  |             | + deliver(cargo)   |
  | + plan_delivery(cargo)|             +--------------------+
  +-----------------------+                  ^         ^
        ^             ^                      |         |
        |             |                 +--------+  +--------+
+---------------+ +--------------+      | Truck  |  |  Ship  |
| RoadLogistics | | SeaLogistics |      +--------+  +--------+
+---------------+ +--------------+      |+deliver|  |+deliver|
|+create_       | |+create_      |      +--------+  +--------+
| transport()   | | transport()  |
+---------------+ +--------------+
```

#### 2.4. Пояснення реалізації

Клас `Logistics` містить бізнес-логіку `plan_delivery()`, яка викликає фабричний метод `create_transport()` і працює з результатом через інтерфейс `Transport`. Який саме транспорт буде створено, визначає підклас: `RoadLogistics` повертає `Truck`, `SeaLogistics` — `Ship`. Щоб додати новий вид транспорту (наприклад, літак), достатньо створити класи `Plane` і `AirLogistics`, не змінюючи наявний код.
