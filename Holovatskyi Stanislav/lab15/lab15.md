### Мета роботи

Познайомитися з основними принципами та найбільш поширеними техніками рефакторингу програмного забезпечення.

### 1. Загальний опис принципів рефакторингу

**Рефакторинг** — це зміна внутрішньої структури програми без зміни її зовнішньої поведінки з метою покращити зрозумілість, спростити підтримку та зменшити технічний борг (М. Фаулер).

Основні принципи рефакторингу:

- **Збереження поведінки** — після рефакторингу програма виконує ті самі функції, що й до нього;
- **Малі кроки** — виконується один невеликий рефакторинг за раз, після кожного кроку запускаються тести;
- **Наявність тестів** — автоматичні тести є страхувальною сіткою; без них рефакторинг ризикований;
- **Рефакторинг окремо від нових функцій** — не змішувати зміну структури з додаванням функціональності (правило «двох капелюхів»);
- **Використання системи контролю версій** — кожен крок фіксується комітом, щоб за потреби його можна було відкотити;
- **Правило трьох** — перше дублювання допускається, друге викликає сумнів, на третє слід рефакторити;
- **Коли рефакторити** — перед додаванням функціональності, під час виправлення помилки, під час code review.

### 2. Основні техніки рефакторингу

| Група | Техніки |
| --- | --- |
| Композиція методів | Extract Method, Inline Method, Extract Variable, Replace Temp with Query |
| Переміщення між об'єктами | Move Method, Move Field, Extract Class, Inline Class |
| Організація даних | Replace Magic Number with Constant, Encapsulate Field, Replace Data Value with Object |
| Спрощення умовних виразів | Decompose Conditional, Consolidate Conditional, Replace Conditional with Polymorphism, Guard Clauses |
| Спрощення викликів методів | Rename Method, Add/Remove Parameter, Introduce Parameter Object |
| Робота із узагальненням | Pull Up / Push Down Method, Extract Superclass / Interface, Replace Inheritance with Delegation |

#### 2.1. Детальний опис техніки Extract Method (Виділення методу)

**Проблема:** є фрагмент коду, який можна згрупувати за змістом і який ускладнює читання довгого методу.

**Рішення:** перенести цей фрагмент в окремий метод (функцію) з назвою, що пояснює його призначення, а на місці фрагмента викликати новий метод.

**Порядок виконання:**

1. Створити новий метод і дати йому назву, що описує *що він робить*, а не *як*.
2. Скопіювати в нього потрібний фрагмент коду.
3. Передати як параметри змінні, які використовуються у фрагменті, а результат повернути через `return`.
4. Замінити початковий фрагмент викликом нового методу.
5. Запустити тести.

**До рефакторингу:**

```
def print_order(order):
    total = 0
    for item in order['items']:
        total += item['price'] * item['qty']
    if total > 1000:
        total = total * 0.95
    print('Клієнт:', order['customer'])
    print('Сума до сплати:', total)
```

**Після рефакторингу (Extract Method + Replace Magic Number with Constant):**

```
DISCOUNT_THRESHOLD = 1000
DISCOUNT_RATE = 0.05


def calculate_total(items):
    return sum(item['price'] * item['qty'] for item in items)


def apply_discount(total):
    if total > DISCOUNT_THRESHOLD:
        return total * (1 - DISCOUNT_RATE)
    return total


def print_header(order):
    print('Клієнт:', order['customer'])


def print_order(order):
    total = apply_discount(calculate_total(order['items']))
    print_header(order)
    print('Сума до сплати:', total)
```

**Результат:** кожна функція виконує одну задачу (відповідає SRP), код читається як текст, а логіку знижки можна змінювати й тестувати окремо.

### 3. Запахи коду

**Запах коду (code smell)** — ознака в коді, що вказує на можливу глибшу проблему дизайну. Це не помилка, а сигнал, що код варто переглянути.

Групи запахів:

- **Роздуті (Bloaters):** Long Method, Large Class, Primitive Obsession, Long Parameter List, Data Clumps;
- **Зловживання ООП:** Switch Statements, Temporary Field, Refused Bequest;
- **Перешкоди змінам:** Divergent Change, Shotgun Surgery;
- **Зайве (Dispensables):** Duplicate Code, Dead Code, Lazy Class, Data Class, Speculative Generality, надлишкові коментарі;
- **Надмірна зв'язаність:** Feature Envy, Inappropriate Intimacy, Message Chains, Middle Man.

#### 3.1. Детальний опис запаху Long Method (Довгий метод)

**Ознаки:** метод містить понад 10–20 рядків, багато вкладених умов і циклів, його складно описати однією фразою, потрібні коментарі всередині, щоб зрозуміти окремі блоки.

**Причини:** код «наростає» поступово — до методу щоразу додають кілька рядків, а виділити окремий метод лінуються.

**Наслідки:** важко читати, тестувати й повторно використовувати; зміни викликають помилки; порушується принцип єдиної відповідальності.

**Способи усунення:**

- Extract Method — виділити змістовні блоки в окремі методи;
- Replace Temp with Query — замінити тимчасові змінні викликами методів;
- Introduce Parameter Object / Preserve Whole Object — скоротити списки параметрів;
- Replace Method with Method Object — перетворити складний метод на окремий клас;
- Decompose Conditional — винести умови й гілки в методи.

**Приклад:** функція `print_order()` з розділу 2.1 до рефакторингу містила розрахунок суми, знижку й виведення — тобто три відповідальності. Після виділення методів вона стала короткою.

### 4. Збереження функціоналу під час рефакторингу

- Перед початком написати (або запустити наявні) автоматичні тести;
- працювати малими кроками й запускати тести після кожного;
- використовувати Git: кожен успішний крок — окремий коміт;
- застосовувати автоматичні рефакторинги IDE (PyCharm, VS Code), які менш схильні до помилок;
- проводити code review та використовувати статичний аналіз (pylint, flake8, SonarQube).

У ході роботи розглянуто принципи й техніки рефакторингу. Детально описано техніку Extract Method та запах коду Long Method. Показано, що рефакторинг покращує читабельність і підтримуваність коду без зміни його поведінки, за умови наявності тестів і малих кроків.
