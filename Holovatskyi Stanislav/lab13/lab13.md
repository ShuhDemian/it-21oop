### Мета роботи

Познайомитися з групою структурних шаблонів проєктування.

### 1. Теоретичний опис групи структурних шаблонів

**Структурні шаблони** описують, як з класів та об'єктів будувати більші структури, зберігаючи їх гнучкими й ефективними. Вони розв'язують проблеми композиції: несумісні інтерфейси, надмірне успадкування, складність підсистем, великі витрати пам'яті.

Основні структурні шаблони:

- **Adapter (Адаптер)** — перетворює інтерфейс одного класу на інтерфейс, якого очікує клієнт;
- **Bridge (Міст)** — розділяє абстракцію та реалізацію на дві незалежні ієрархії;
- **Composite (Компонувальник)** — об'єднує об'єкти в дерево «частина-ціле»;
- **Decorator (Декоратор)** — динамічно додає об'єкту нову поведінку;
- **Facade (Фасад)** — надає спрощений інтерфейс до складної підсистеми;
- **Flyweight (Легковаговик)** — економить пам'ять, розділяючи спільний стан між об'єктами;
- **Proxy (Заступник)** — підміняє об'єкт і контролює доступ до нього.

### 2. Шаблон «Адаптер» (Adapter)

#### 2.1. Теоретичний опис

**Адаптер** — структурний шаблон, що дозволяє об'єктам із несумісними інтерфейсами працювати разом. Адаптер реалізує інтерфейс, який очікує клієнт, і всередині перетворює виклики на виклики адаптованого класу. Це корисно, коли потрібно використати існуючий клас (бібліотеку, застарілий код), змінити який неможливо або недоцільно.

Учасники шаблону:

- **Client** — клас із бізнес-логікою, що працює лише з інтерфейсом Target;
- **Target** — інтерфейс, який розуміє клієнт;
- **Adaptee** — існуючий клас із несумісним інтерфейсом;
- **Adapter** — реалізує Target і містить посилання на Adaptee (об'єктний адаптер), перетворюючи виклики та дані.

Переваги: відповідність принципам SRP та OCP, повторне використання існуючого коду без його зміни. Недолік: з'являються додаткові класи.

#### 2.2. Приклад реалізації коду (Python)

Застарілий сервіс повертає дані у форматі XML, а клієнтський код очікує словник (JSON-подібну структуру). Адаптер виконує перетворення.

```
import xml.etree.ElementTree as ET


class LegacyXmlService:                    # Adaptee
    def fetch_xml(self):
        return '<student><name>Іван</name><age>20</age></student>'


class JsonService:                         # Target
    def get_data(self):
        raise NotImplementedError


class XmlToJsonAdapter(JsonService):       # Adapter
    def __init__(self, adaptee):
        self.adaptee = adaptee

    def get_data(self):
        root = ET.fromstring(self.adaptee.fetch_xml())
        return {child.tag: child.text for child in root}


class Client:                              # Client
    def __init__(self, service):
        self.service = service

    def show(self):
        data = self.service.get_data()
        print('Студент:', data['name'], '| вік:', data['age'])


if __name__ == '__main__':
    adapter = XmlToJsonAdapter(LegacyXmlService())
    Client(adapter).show()
```

Результат виконання:

```
Студент: Іван | вік: 20
```

#### 2.3. UML-діаграма класів

```
+----------+     uses     +------------------+
|  Client  |------------->| JsonService      |
+----------+              |  (Target)        |
| + show() |              +------------------+
+----------+              | + get_data()     |
                          +------------------+
                                   ^
                                   |
                          +------------------+   adapts   +--------------------+
                          | XmlToJsonAdapter |----------->| LegacyXmlService   |
                          +------------------+            |   (Adaptee)        |
                          | - adaptee        |            +--------------------+
                          | + get_data()     |            | + fetch_xml()      |
                          +------------------+            +--------------------+
```

#### 2.4. Пояснення реалізації

Клас `Client` працює лише з інтерфейсом `JsonService` і нічого не знає про XML. Клас `XmlToJsonAdapter` реалізує цей інтерфейс, отримує XML від `LegacyXmlService`, розбирає його та повертає словник. Якщо в майбутньому з'явиться інше джерело даних, достатньо написати новий адаптер, не змінюючи клієнта.
