### Мета роботи

Познайомитися з групою поведінкових шаблонів проєктування.

### 1. Теоретичний опис групи поведінкових шаблонів

**Поведінкові шаблони** відповідають за ефективну взаємодію між об'єктами та розподіл відповідальностей між ними. Вони описують алгоритми й способи комунікації, зменшуючи зв'язаність між відправником та одержувачем.

Основні поведінкові шаблони:

- **Chain of Responsibility (Ланцюжок обов'язків)** — передає запит по ланцюжку обробників;
- **Command (Команда)** — інкапсулює запит як об'єкт;
- **Iterator (Ітератор)** — послідовний доступ до елементів колекції;
- **Mediator (Посередник)** — централізує взаємодію об'єктів;
- **Memento (Знімок)** — зберігає та відновлює стан об'єкта;
- **Observer (Спостерігач)** — сповіщає залежні об'єкти про зміну стану;
- **State (Стан)** — змінює поведінку об'єкта залежно від стану;
- **Strategy (Стратегія)** — інкапсулює взаємозамінні алгоритми;
- **Template Method (Шаблонний метод)** — задає скелет алгоритму в базовому класі;
- **Visitor (Відвідувач)** — додає нові операції без зміни класів.

### 2. Шаблон «Спостерігач» (Observer)

#### 2.1. Теоретичний опис

**Спостерігач** визначає залежність «один до багатьох» між об'єктами: при зміні стану одного об'єкта (суб'єкта) усі залежні від нього об'єкти (спостерігачі) автоматично отримують сповіщення. Інша назва — Publish/Subscribe.

Учасники шаблону:

- **Subject** — зберігає список спостерігачів, має методи `attach`, `detach`, `notify`;
- **Observer** — інтерфейс із методом `update()`;
- **ConcreteSubject** — зберігає стан і викликає `notify()` при його зміні;
- **ConcreteObserver** — реалізує `update()` і реагує на зміну.

Переваги: слабка зв'язаність суб'єкта та спостерігачів, динамічна підписка й відписка. Недоліки: порядок сповіщення не гарантований, можливі витоки пам'яті при забутих підписках.

#### 2.2. Приклад реалізації коду (Python)

```
from abc import ABC, abstractmethod


class Observer(ABC):                       # Observer
    @abstractmethod
    def update(self, temperature):
        pass


class WeatherStation:                      # ConcreteSubject
    def __init__(self):
        self._observers = []
        self._temperature = None

    def attach(self, observer):
        self._observers.append(observer)

    def detach(self, observer):
        self._observers.remove(observer)

    def notify(self):
        for observer in self._observers:
            observer.update(self._temperature)

    def set_temperature(self, value):
        self._temperature = value
        self.notify()


class PhoneDisplay(Observer):              # ConcreteObserver
    def update(self, temperature):
        print('Телефон: температура', temperature, '°C')


class WebDisplay(Observer):                # ConcreteObserver
    def update(self, temperature):
        print('Вебсайт: температура', temperature, '°C')


if __name__ == '__main__':
    station = WeatherStation()
    phone = PhoneDisplay()
    web = WebDisplay()

    station.attach(phone)
    station.attach(web)
    station.set_temperature(21)

    station.detach(phone)
    station.set_temperature(25)
```

Результат виконання:

```
Телефон: температура 21 °C
Вебсайт: температура 21 °C
Вебсайт: температура 25 °C
```

#### 2.3. UML-діаграма класів

```

|   WeatherStation     |<>---------->|  Observer (ABC)     |
|    (Subject)         |     0..*    +---------------------+
+----------------------+             | + update(temp)      |
| - _observers         |             +---------------------+
| - _temperature       |                  ^          ^
+----------------------+                  |          |
| + attach(observer)   |          +--------------+ +-------------+
| + detach(observer)   |          | PhoneDisplay | | WebDisplay  |
| + notify()           |          +--------------+ +-------------+
| + set_temperature(v) |          | + update()   | | + update()  |
+----------------------+          +--------------+ +-------------+
```

#### 2.4. Пояснення реалізації

Метеостанція (`WeatherStation`) зберігає список підписників. Метод `set_temperature()` змінює стан і викликає `notify()`, який по черзі викликає `update()` у кожного спостерігача. Після `detach(phone)` телефон більше не отримує оновлень, тому при другій зміні температури виводиться лише рядок для вебсайту. Станція не знає конкретних класів спостерігачів — лише їхній інтерфейс.
