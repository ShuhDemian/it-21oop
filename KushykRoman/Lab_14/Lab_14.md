## Завдання 1. Теоретичний опис поведінкової групи шаблонів

**Поведінкові шаблони (Behavioral patterns)** — це шаблони проєктування, які відповідають за ефективну комунікацію між об'єктами та правильний розподіл обов'язків між ними.

Якщо твірні шаблони вирішують питання *створення* об'єктів, а структурні — їхнього *компонування*, то поведінкові зосереджені на тому, як об'єкти *взаємодіють* один з одним. Вони допомагають зробити алгоритми та обмін повідомленнями між класами більш гнучкими, зменшуючи жорстку залежність об'єктів один від одного.

## Завдання 2. Індивідуальне завдання (на прикладі шаблону «Спостерігач»)

### Теоретичний опис шаблону

**Спостерігач (Observer / Publish-Subscribe)** — це поведінковий шаблон, який створює механізм підписки. Він дозволяє одним об'єктам стежити і реагувати на події, що відбуваються в інших об'єктах.

**Аналогія з життя:** Підписка на YouTube-канал або розсилку новин. Ви (Спостерігач) підписуєтесь на канал (Видавець). Коли на каналі виходить нове відео, всі підписники автоматично отримують сповіщення, і їм не потрібно кожну хвилину перевіряти сторінку каналу вручну.

### Приклад коду на Python

Реалізуємо систему підписки на YouTube-канал.

```python
from abc import ABC, abstractmethod

# ==========================================
# 1. Інтерфейси для Видавця та Спостерігача
# ==========================================

class Observer(ABC):
    """Інтерфейс підписника"""
    @abstractmethod
    def update(self, video_title: str):
        pass

class Subject(ABC):
    """Інтерфейс каналу (видавця)"""
    @abstractmethod
    def attach(self, observer: Observer):
        pass
    
    @abstractmethod
    def detach(self, observer: Observer):
        pass
    
    @abstractmethod
    def notify(self):
        pass

# ==========================================
# 2. Конкретні реалізації
# ==========================================

class YouTubeChannel(Subject):
    def __init__(self, name: str):
        self.name = name
        self._subscribers = []  # Список підписників
        self.latest_video = ""

    def attach(self, observer: Observer):
        self._subscribers.append(observer)

    def detach(self, observer: Observer):
        self._subscribers.remove(observer)

    def notify(self):
        """Сповіщаємо всіх підписників зі списку"""
        for subscriber in self._subscribers:
            subscriber.update(self.latest_video)

    def release_video(self, video_title: str):
        """Подія: вихід нового відео"""
        self.latest_video = video_title
        print(f"\n[Канал {self.name}] випустив нове відео: '{self.latest_video}'")
        self.notify() # Автоматично сповіщаємо всіх


class Subscriber(Observer):
    def __init__(self, name: str):
        self.name = name

    def update(self, video_title: str):
        """Реакція підписника на сповіщення"""
        print(f" -> Користувач {self.name} отримав сповіщення: Дивитись відео '{video_title}'!")


# ==========================================
# 3. Перевірка роботи коду
# ==========================================
if __name__ == "__main__":
    # Створюємо канал
    it_channel = YouTubeChannel("IT-Програмування")

    # Створюємо підписників
    user1 = Subscriber("Олексій")
    user2 = Subscriber("Марія")

    # Підписуємо їх на канал
    it_channel.attach(user1)
    it_channel.attach(user2)

    # Канал випускає відео — підписники автоматично отримують сповіщення
    it_channel.release_video("Вступ до Python")

    # Марія відписується
    it_channel.detach(user2)

    # Канал випускає друге відео (отримає лише Олексій)
    it_channel.release_video("Шаблони проєктування")

```

### UML-діаграма (Опис структури)

Структура патерну Спостерігач складається з таких елементів:

1. **Subject (`Subject`)**: Інтерфейс, який оголошує методи для керування підписниками (додавання, видалення, сповіщення).
2. **ConcreteSubject (`YouTubeChannel`)**: Зберігає стан, який цікавий спостерігачам. Коли стан змінюється (виходить відео), він викликає метод `notify()` для всіх спостерігачів зі свого списку.
3. **Observer (`Observer`)**: Інтерфейс, який описує метод `update()`. Через нього Видавець передає оновлення.
4. **ConcreteObserver (`Subscriber`)**: Реалізує метод `update()`. Отримує сповіщення і виконує відповідну дію (наприклад, виводить повідомлення на екран).

*(Залежності: Видавець містить список об'єктів типу Спостерігач (Агрегація). Конкретні класи реалізують відповідні інтерфейси).*
## Запитання для самоконтролю

### 1. Що таке поведінкові шаблони?

**Відповідь:** Це шаблони проєктування, які вирішують завдання ефективної взаємодії між об'єктами. Вони допомагають зменшити зв'язність класів при обміні повідомленнями та розподілі обов'язків, роблячи програму більш модульною та гнучкою до змін.

### 2. Які поведінкові шаблони Вам відомі?

**Відповідь:** До найвідоміших поведінкових шаблонів (за класифікацією GoF) належать:

1. **Спостерігач (Observer)** — механізм підписки на події.
2. **Стратегія (Strategy)** — інкапсулює сімейство алгоритмів і дозволяє змінювати їх під час виконання програми.
3. **Стан (State)** — дозволяє об'єкту змінювати свою поведінку залежно від внутрішнього стану.
4. **Команда (Command)** — перетворює запит на самостійний об'єкт.
5. **Ланцюжок обов'язків (Chain of Responsibility)** — передає запит ланцюжком обробників.
6. **Ітератор (Iterator)** — дозволяє послідовно обходити елементи колекції.
7. **Зберігач (Memento)** — зберігає та відновлює минулий стан об'єкта без розкриття його деталей.
8. **Шаблонний метод (Template Method)** — визначає кістяк алгоритму, дозволяючи підкласам змінювати його кроки.
9. **Посередник (Mediator)** — зменшує прямі зв'язки між класами, змушуючи їх спілкуватися через єдиний об'єкт-посередник.
10. **Відвідувач (Visitor)** — дозволяє додавати нові операції до об'єктів без зміни їхніх класів.

### 3. Поясніть як реалізовано шаблон у Вашому прикладі.

**Відповідь:** У прикладі шаблон «Спостерігач» реалізовано так, що клас `YouTubeChannel` (Видавець) не знає деталей про конкретних користувачів, які на нього підписані. Він лише зберігає список об'єктів, які реалізують загальний інтерфейс `Observer`.
Коли викликається метод `release_video()`, канал просто проходить циклом по своєму списку підписників (`self._subscribers`) і для кожного викликає метод `update()`. Таким чином досягається слабка зв'язність: ми можемо додавати сотні нових класів-підписників, і код каналу при цьому взагалі не доведеться змінювати.
