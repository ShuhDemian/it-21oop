## Завдання 1 та 3. Різниця між методами та створення "Методу класу" (Class Method)

*   **Звичайні методи (Instance methods):** Працюють з конкретним об'єктом. Вони завжди приймають параметр `self` (посилання на сам об'єкт) і можуть змінювати його унікальні властивості.
*   **Методи класу (Class methods):** Працюють не з конкретним об'єктом, а з усім класом загалом. Замість `self` вони приймають параметр `cls` (посилання на сам клас). Щоб Python зрозумів, що це метод класу, над ним ставлять спеціальну позначку (декоратор) `@classmethod`. Вони ідеально підходять для роботи зі змінними класу.

```python
class Employee:
    company_name = "TechCorp"
    
    def __init__(self, name, position):
        self.name = name
        self.position = position
        
    def get_info(self):
        return f"{self.name} працює на посаді {self.position} у {self.company_name}."

    @classmethod
    def change_company_name(cls, new_name):
        cls.company_name = new_name
        print(f"Увага! Назву компанії змінено на {cls.company_name} для всіх працівників.")

emp1 = Employee("Іван", "Розробник")
emp2 = Employee("Олена", "Тестувальник")

Employee.change_company_name("GlobalTech Solutions")

print(emp1.get_info())
print(emp2.get_info())
```

## Завдання 2 та 4. Альтернативні конструктори
У багатьох мовах програмування можна створити кілька методів `__init__`, які приймають різні дані. У Python метод `__init__` може бути лише один. Що робити, якщо ми хочемо створювати об'єкт не передаючи окремо ім'я і посаду, а, наприклад, "витягуючи" їх з одного рядка тексту (наприклад, `"Марія-Дизайнер"`)? 
Для цього використовують методи класу (`@classmethod`). Вони створюють об'єкт, підготовлюють дані та повертають новий екземпляр класу (`cls(...)`). Це і є "альтернативний конструктор".

```python
class Employee:
    def __init__(self, name, position):
        self.name = name
        self.position = position

    @classmethod
    def from_string(cls, employee_string):
        name, position = employee_string.split("-")
        return cls(name, position)

emp1 = Employee("Ігор", "Менеджер")

emp_str = "Анна-Аналітик"
emp2 = Employee.from_string(emp_str)

print(f"Створено класично: {emp1.name}, {emp1.position}")
print(f"Створено з рядка: {emp2.name}, {emp2.position}")
```


## Завдання 5. Створення статичного методу

Статичні методи (`@staticmethod`) взагалі не приймають ані `self`, ані `cls`. Вони не мають доступу ні до властивостей конкретного об'єкта, ні до змінних класу. 
Навіщо вони тоді потрібні? Це просто звичайні функції, які логічно пов'язані з класом, і їх зручно тримати всередині нього для порядку. Вони просто беруть вхідні дані і щось повертають.

```python
import datetime

class Employee:
    def __init__(self, name):
        self.name = name

    @staticmethod
    def is_workday(day):
        if day.weekday() == 5 or day.weekday() == 6:
            return False
        return True

today = datetime.date.today()
sunday = datetime.date(2023, 10, 22) 
print(f"Сьогодні робочий день? - {Employee.is_workday(today)}")
print(f"22.10.2023 було робочим днем? - {Employee.is_workday(sunday)}")
```


## Запитання для самоконтролю

**1. В чому полягає різниця між звичайними методами та методами класу?**
*   **Звичайний метод** обов'язково приймає параметр `self` і працює з даними **конкретного об'єкта**. Якщо в нас 10 працівників, звичайний метод змінюватиме зарплату лише тому, для кого він викликаний.
*   **Метод класу** (з декоратором `@classmethod`) обов'язково приймає параметр `cls` і працює з **самим класом**. Він може змінювати змінні класу, що миттєво вплине на всі існуючі та майбутні об'єкти цього класу.

**2. Що таке “альтернативний конструктор”? Для чого його можна застосовувати?**
Альтернативний конструктор — це метод класу (з декоратором `@classmethod`), який створює і повертає новий об'єкт цього ж класу (`return cls(...)`), але приймає вхідні дані в іншому форматі, ніж стандартний метод `__init__`.
Він застосовується, коли дані для створення об'єкта надходять у незручному вигляді (наприклад, суцільним рядком з файлу, зі словника JSON, або з бази даних), і їх потрібно попередньо "розібрати" на частини перед тим, як передати в `__init__`.

**3. Для чого потрібні статичні методи? Чи можливо обійтися без використання статичних методів у ООП?**
Статичні методи (з декоратором `@staticmethod`) потрібні для виконання допоміжних операцій, які логічно стосуються тематики класу, але не потребують доступу до його внутрішніх змінних чи стану. Це просто утилітарні функції (наприклад, перевірка правильності формату пошти або розрахунок податку за формулою).
**Чи можна без них обійтися? Так, абсолютно.** Будь-який статичний метод можна просто винести за межі класу і зробити звичайною функцією в модулі Python. Проте використання `@staticmethod` дозволяє краще організувати код: якщо функція стосується суто працівників, логічно зберігати її всередині класу `Employee`.
