## Завдання 1. Теоретичний опис твірної групи шаблонів

**Твірні шаблони (Creational patterns)** — це шаблони проєктування, які абстрагують і контролюють процес створення екземплярів класів (об'єктів).

Основна проблема, яку вони вирішують: пряме створення об'єктів (через оператор або виклик класу безпосередньо) часто міцно прив'язує код до конкретних класів. Це ускладнює подальше розширення програми. Твірні шаблони дозволяють приховати логіку створення об'єктів і зробити архітектуру більш гнучкою. Вони допомагають системі самій вирішувати, *які* саме об'єкти потрібно створити, *як* і *коли*.


## Завдання 2. Індивідуальне завдання (на прикладі шаблону «Фабричний метод»)

### Теоретичний опис шаблону

**Фабричний метод (Factory Method)** — це твірний шаблон проєктування, який визначає загальний інтерфейс для створення об'єктів у суперкласі, але дозволяє підкласам змінювати тип створюваних об'єктів.

Замість того, щоб викликати конструктор класу напряму, розробник викликає спеціальний "фабричний" метод. Цей метод повертає об'єкт, але конкретний тип цього об'єкта визначається дочірніми класами (фабриками).

### Приклад коду на Python

Уявімо систему сповіщень, яка може відправляти повідомлення користувачам. Ми хочемо мати можливість відправляти як Email, так і SMS, при цьому не змінюючи основну логіку програми.

```python
from abc import ABC, abstractmethod

# 1. Загальний інтерфейс об'єкта (Продукту)
class Notifier(ABC):
    @abstractmethod
    def send(self, message: str):
        pass

# 2. Конкретні продукти (реалізації інтерфейсу)
class EmailNotifier(Notifier):
    def send(self, message: str):
        print(f"Відправка Email з текстом: '{message}'")

class SMSNotifier(Notifier):
    def send(self, message: str):
        print(f"Відправка SMS з текстом: '{message}'")

# 3. Базовий клас "Творець" (Фабрика)
class NotificationFactory(ABC):
    @abstractmethod
    def create_notifier(self) -> Notifier:
        """Фабричний метод, який мають реалізувати підкласи"""
        pass
    
    def notify_user(self, message: str):
        # Базовий клас викликає фабричний метод, щоб отримати потрібний об'єкт
        notifier = self.create_notifier()
        notifier.send(message)

# 4. Конкретні фабрики, які вирішують, який об'єкт створити
class EmailNotificationFactory(NotificationFactory):
    def create_notifier(self) -> Notifier:
        return EmailNotifier()

class SMSNotificationFactory(NotificationFactory):
    def create_notifier(self) -> Notifier:
        return SMSNotifier()


# --- Перевірка роботи коду ---
if __name__ == "__main__":
    print("Клієнтський код використовує Email-фабрику:")
    email_factory = EmailNotificationFactory()
    email_factory.notify_user("Вітаємо на курсі!")

    print("\nКлієнтський код використовує SMS-фабрику:")
    sms_factory = SMSNotificationFactory()
    sms_factory.notify_user("Ваш код підтвердження: 1234")

```

### UML-діаграма (Опис структури)

У класичній UML-діаграмі Фабричного методу є 4 ключові сутності, які відображені в нашому коді:

1. **Product (`Notifier`)**: Абстрактний інтерфейс об'єктів, які створюються.
2. **ConcreteProduct (`EmailNotifier`, `SMSNotifier`)**: Конкретні класи, що реалізують інтерфейс Product.
3. **Creator (`NotificationFactory`)**: Абстрактний клас-фабрика, який оголошує фабричний метод `create_notifier()`. Цей метод має повертати тип `Product`.
4. **ConcreteCreator (`EmailNotificationFactory`, `SMSNotificationFactory`)**: Класи-спадкоємці, які безпосередньо реалізують фабричний метод і повертають `ConcreteProduct`.

*(Залежності: Конкретні творці успадковуються від абстрактного Творця. Конкретні продукти успадковуються від абстрактного Продукту. Кожен конкретний творець пов'язаний лінією створення (dependency) зі своїм конкретним продуктом).*

## Запитання для самоконтролю

### 1. Що таке твірні шаблони?

**Відповідь:** Твірні шаблони — це патерни проєктування, які вирішують завдання безпечного та гнучкого створення об'єктів. Вони приховують деталі ініціалізації екземплярів класів від основного коду, зменшуючи його залежність від конкретних реалізацій.

### 2. Які твірні шаблони Вам відомі?

**Відповідь:** До класичної групи твірних шаблонів (за книгою "Банди чотирьох" - GoF) належать п'ять патернів:

1. **Фабричний метод (Factory Method)**.
2. **Абстрактна фабрика (Abstract Factory)** — створення сімейств пов'язаних об'єктів.
3. **Одинак (Singleton)** — гарантує існування лише одного екземпляра класу в усій програмі.
4. **Будівельник (Builder)** — дозволяє створювати складні об'єкти покроково.
5. **Прототип (Prototype)** — створення нових об'єктів шляхом клонування вже існуючого об'єкта.

### 3. Поясніть як реалізовано шаблон у Вашому прикладі.

**Відповідь:** У моєму коді патерн «Фабричний метод» реалізовано так: базова логіка сповіщення (`NotificationFactory`) не знає, яким саме чином буде надіслано повідомлення (пошта чи телефон). Вона лише знає, що метод `create_notifier()` поверне їй об'єкт, який має функцію `send()`.
Рішення про те, який саме об'єкт (Email чи SMS) ініціалізувати, перекладено на дочірні класи-фабрики (`EmailNotificationFactory` та `SMSNotificationFactory`). Завдяки цьому ми зможемо в майбутньому легко додати, наприклад, `TelegramNotifier`, не змінюючи вже існуючий код базової фабрики та системи сповіщень.
