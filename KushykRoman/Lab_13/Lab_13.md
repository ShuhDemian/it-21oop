## Завдання 1. Теоретичний опис структурної групи шаблонів

**Структурні шаблони (Structural patterns)** — це шаблони, які відповідають за те, як саме класи та об'єкти об'єднуються у більші, складніші структури.

Основна ідея полягає в тому, щоб зробити ці зв'язки гнучкими та ефективними. Якщо твірні шаблони відповідають на питання *"Як створити об'єкт?"*, то структурні відповідають на питання *"Як правильно поєднати об'єкти між собою, щоб зміна однієї частини не зламала всю систему?"*. Вони активно використовують наслідування та композицію для побудови зручних інтерфейсів.

## Завдання 2. Індивідуальне завдання (на прикладі шаблону «Адаптер»)

### Теоретичний опис шаблону

**Адаптер (Adapter або Wrapper)** — це структурний шаблон проєктування, який дозволяє об'єктам із несумісними інтерфейсами працювати разом.

Принцип роботи схожий на звичайний перехідник для розеток. Якщо у вас є американська вилка, а розетка європейська — ви використовуєте адаптер. У програмуванні адаптер бере виклики до одного об'єкта і перетворює їх у формат, який розуміє інший об'єкт (наприклад, перетворює дані з формату JSON у формат XML для сторонньої бібліотеки).

### Приклад коду на Python

Уявімо, що наша програма очікує отримати звичайний текст, але стороння бібліотека (або стара підсистема) повертає текст задом наперед. Ми напишемо Адаптер, який виправлятиме це на льоту.

```python
# 1. Інтерфейс, з яким звикла працювати наша програма (Target)
class StandardSystem:
    def get_data(self) -> str:
        return "Зрозумілі дані"

# 2. Стороння система, яка має інший (несумісний) формат роботи (Adaptee)
class LegacySystem:
    def get_weird_data(self) -> str:
        # Повертає текст задом наперед
        return "інад ітимизропЕн"

# 3. Клас-Адаптер, який робить стару систему сумісною з новою
class Adapter(StandardSystem):
    def __init__(self, legacy_system: LegacySystem):
        self.legacy_system = legacy_system

    def get_data(self) -> str:
        # Отримуємо незрозумілі дані
        weird_data = self.legacy_system.get_weird_data()
        # Перетворюємо їх у нормальний формат (перевертаємо рядок)
        normal_data = weird_data[::-1]
        return f"Адаптер виправив дані: {normal_data}"

# --- Перевірка роботи коду ---
if __name__ == "__main__":
    print("1. Звичайна система:")
    system = StandardSystem()
    print(system.get_data())

    print("\n2. Стара система напряму (не сумісна з нашими очікуваннями):")
    legacy = LegacySystem()
    print(legacy.get_weird_data())

    print("\n3. Використання Адаптера:")
    # Обертаємо стару систему в адаптер
    adapter = Adapter(legacy) 
    print(adapter.get_data())

```

### UML-діаграма (Опис структури)

Структура Адаптера складається з наступних елементів:

1. **Target (`StandardSystem`)**: Клас або інтерфейс, який описує стандарти роботи нашої програми.
2. **Adaptee (`LegacySystem`)**: Об'єкт, з яким ми хочемо взаємодіяти, але не можемо зробити це напряму через його несумісний інтерфейс.
3. **Adapter (`Adapter`)**: Клас, який успадковується (або реалізовує) інтерфейс `Target` і всередині себе містить посилання на об'єкт `Adaptee`. Він викликає методи `Adaptee`, перетворюючи їх результат на той, що вимагає `Target`.
4. **Client**: Клієнтський код, який спілкується з будь-яким об'єктом, що підтримує інтерфейс `Target`.

*(Залежності: Адаптер реалізує інтерфейс Target. Також Адаптер має агрегацію (композицію) з класом Adaptee, тобто містить його всередині себе як поле).*

## Запитання для самоконтролю

### 1. Що таке структурні шаблони?

**Відповідь:** Це патерни, що допомагають створювати гнучкі та розширювані структури класів та об'єктів. Вони вирішують проблеми несумісності інтерфейсів, спрощують роботу зі складними системами (композиція об'єктів) та дозволяють динамічно додавати нову поведінку без зміни наявного коду.

### 2. Які структурні шаблони Вам відомі?

**Відповідь:** За класифікацією GoF («Банди чотирьох») існують 7 основних структурних шаблонів:

1. **Адаптер (Adapter)** — перетворює інтерфейс одного класу на інший, який очікують клієнти.
2. **Декоратор (Decorator)** — динамічно додає об'єкту нові обов'язки (обгортає об'єкт).
3. **Фасад (Facade)** — надає простий інтерфейс до складної підсистеми.
4. **Міст (Bridge)** — відокремлює абстракцію від її реалізації.
5. **Компонувальник (Composite)** — об'єднує об'єкти в деревоподібну структуру для роботи з ними як з єдиним цілим.
6. **Замісник (Proxy)** — надає сурогатний об'єкт, який контролює доступ до оригінального об'єкта.
7. **Легковаговик (Flyweight)** — дозволяє вмістити велику кількість об'єктів в оперативній пам'яті, розділяючи між ними спільний стан.

### 3. Поясніть як реалізовано шаблон у Вашому прикладі.

**Відповідь:** У моєму прикладі шаблон «Адаптер» реалізовано через композицію об'єктів. Програма хоче викликати метод `get_data()`. Стара система (`LegacySystem`) такого методу не має (у неї є лише `get_weird_data()`), і ми не можемо її змінити.
Тому ми створили клас `Adapter`. Він має потрібний метод `get_data()`, у якому "ховається" виклик `get_weird_data()` старої системи, а також відбувається перетворення результату в зрозумілий для нас формат (текст перевертається в правильному порядку). Програма взаємодіє тільки з Адаптером, навіть не підозрюючи про існування старої системи.
