## Завдання 1. Види тестів та піраміда тестування

**Тестування програмного забезпечення** — це процес перевірки програми на відповідність заявленим вимогам та пошук помилок (багів).

Щоб тестування було ефективним, використовують концепцію **«Піраміди тестування»** (Testing Pyramid). Вона візуалізує, яких тестів у проєкті має бути найбільше, а яких — найменше.

Піраміда складається з трьох основних рівнів (знизу вгору):

1. **Unit-тести (Модульні тести) — фундамент піраміди.** Їх має бути найбільше. Вони тестують найменші частинки коду (окремі функції або класи) в ізоляції від іншої системи. Працюють дуже швидко.
2. **Integration tests (Інтеграційні тести) — середина піраміди.** Перевіряють, як декілька модулів або компонентів працюють разом (наприклад, чи правильно функція записує дані в реальну базу даних).
3. **End-to-End (E2E / Наскрізні тести) — вершина піраміди.** Їх найменше. Вони імітують поведінку реального користувача від початку до кінця (наприклад, відкривають браузер, клікають кнопки, заповнюють форми). Вони найповільніші та найдорожчі у підтримці.

## Завдання 2. Написання та виконання unit-тесту на Python 3

Для тестування в Python є вбудована бібліотека `unittest`.
Давайте напишемо просту програму (калькулятор) і відразу ж тести до неї, щоб перевірити, чи правильно вона додає числа та чи правильно реагує на ділення на нуль.

### Приклад коду (`calculator_test.py`):

```python
import unittest

# ==========================================
# 1. Код, який ми будемо тестувати (зазвичай в окремому файлі)
# ==========================================
class Calculator:
    def add(self, a, b):
        return a + b

    def divide(self, a, b):
        if b == 0:
            raise ValueError("Ділення на нуль неможливе!")
        return a / b


# ==========================================
# 2. Написання Unit-тестів
# ==========================================
# Клас з тестами обов'язково повинен успадковуватися від unittest.TestCase
class TestCalculator(unittest.TestCase):
    
    # Створюємо об'єкт калькулятора перед кожним тестом
    def setUp(self):
        self.calc = Calculator()

    # Назва тестового методу обов'язково має починатися зі слова 'test_'
    def test_add_positive_numbers(self):
        """Тестуємо додавання додатних чисел"""
        result = self.calc.add(2, 3)
        self.assertEqual(result, 5)  # Перевіряємо, чи результат дорівнює 5

    def test_add_negative_numbers(self):
        """Тестуємо додавання від'ємних чисел"""
        result = self.calc.add(-2, -2)
        self.assertEqual(result, -4)

    def test_divide_normal(self):
        """Тестуємо звичайне ділення"""
        result = self.calc.divide(10, 2)
        self.assertEqual(result, 5.0)

    def test_divide_by_zero(self):
        """Тестуємо, чи викликається помилка при діленні на нуль"""
        # Перевіряємо, чи програма "викине" ValueError
        with self.assertRaises(ValueError):
            self.calc.divide(10, 0)


# ==========================================
# 3. Виконання тестів
# ==========================================
if __name__ == '__main__':
    # Цей рядок запускає всі тести у файлі, якщо запустити скрипт
    unittest.main()

```
## Запитання для самоконтролю

### 1. Для чого потрібне тестування?

**Відповідь:** Тестування необхідне для перевірки того, що програма робить саме те, що від неї очікується. Воно допомагає знаходити помилки ще до того, як програма потрапить до кінцевого користувача, підвищує надійність коду, спрощує рефакторинг (бо тести покажуть, якщо ви щось зламаєте) і слугує своєрідною документацією до коду.

### 2. Які види тестування Вам відомі? Яка між ними різниця? Наведіть переваги та недоліки кожного із них.

**Відповідь:**

* **Unit-тестування (Модульне):**
* *Різниця:* Тестує одну функцію ізольовано.
* *Переваги:* Дуже швидке, легко локалізувати помилку (одразу видно, яка функція зламалась).
* *Недоліки:* Не показує проблеми взаємодії між різними частинами програми.


* **Інтеграційне тестування:**
* *Різниця:* Перевіряє зв'язки між модулями або системою та базою даних/API.
* *Переваги:* Знаходить баги "на стиках" компонентів.
* *Недоліки:* Повільніше за модульні тести, складніше налаштовувати тестове середовище.


* **E2E (Наскрізне) тестування:**
* *Різниця:* Повністю імітує дії користувача.
* *Переваги:* Найвища впевненість, що система працює в реальних умовах.
* *Недоліки:* Дуже повільне виконання, тести часто ламаються (flaky) навіть при дрібних змінах інтерфейсу.



### 3. Як писати та виконувати unit-тести на Python 3?

**Відповідь:**

1. **Як писати:** Необхідно імпортувати вбудований модуль `unittest`. Далі створюється клас, який успадковується від `unittest.TestCase`. Всередині цього класу пишуться методи, назви яких обов'язково починаються з префікса `test_` (наприклад, `test_calculation`). Для перевірки результатів використовуються спеціальні методи assert-ів: `self.assertEqual()`, `self.assertTrue()`, `self.assertRaises()` тощо.
2. **Як виконувати:** Якщо в кінці файлу додати блок `if __name__ == '__main__': unittest.main()`, тести можна запустити як звичайний Python-скрипт: `python tests.py`. Або ж можна запустити їх через консоль за допомогою команди: `python -m unittest tests.py`.
